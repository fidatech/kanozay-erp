# Kanozay ERP — purchasing and inventory development update

Date: 8 November 2026
Branch: `development/kanozay-completion`
Release decision: **development only; no production approval**

## Source changes implemented in this batch

### Purchase orders
- Draft creation gains optional UUID submission protection; the current purchase-order form always sends a token.
- PO creation validates the supplier's enabled purchase currency.
- Confirmation requires at least one item, all items linked to active inventory materials, and an active supplier with the order currency enabled.
- Purchasers can edit the draft header, update line descriptions/materials/quantities/prices, add or remove draft lines and cancel an order with no posted GRN or actual supplier advance.
- Edits and cancellation are restricted to authorized users and posted receipts/financial history are protected.
- The purchase-order detail page now supplies real active warehouses to the GRN receiving selector.
- Posted supplier invoices, remaining payable balances and unapplied supplier advances appear separately from draft purchase estimates.

### Goods receipts and returns
- GRN posting rejects dates earlier than the purchase order and records an audit entry.
- GRN rows link directly to supplier invoice matching and returns.
- Receipt UI reports incoming-lot QC holds and missing material cost layers separately from physically received status.
- Supplier-return register displays actual financial status instead of always showing pending.
- If a GRN has matched supplier invoices, its credit note must use the payable generated by the original GRN and the original inventory-asset offset; returned line quantities must have been invoiced by the selected source invoice.
- Older receipts with no matched invoice still support the existing documented manual payable review path.
- A return after billing cannot produce a negative quantity available for additional supplier invoicing.

### Warehouse stock counts
- New physical counts can target one selected active warehouse or the unassigned stock pool.
- Expected balances are snapshotted by selected location and compared again under locks on approval.
- Approved differences post to the selected warehouse or unassigned pool via the existing immutable inventory adjustment and costing workflow.
- Old counts preserve their legacy company-wide scope rather than being silently reinterpreted.
- The count screen shows balances for the selected warehouse and the review page identifies the location.

### Forms and data integrity
- GRNs, returns, supplier invoice matching, debit notes and landed-cost forms normalize grouped numeric input and Pashto/Dari digits before server-side precision/range validation.
- Supplier invoice credit and inventory valuation remain source-linked. No arbitrary exchange rates or tax policies were introduced.

## Follow-up development — FIFO lot location

The subsequent commit series added location-specific FIFO cost-layer positions, atomic location-preserving warehouse transfers, a QC-released source-lot requirement, audited manual historical lot attribution and a paginated multi-currency warehouse valuation view. See [Warehouse FIFO Lot Location Integration](warehouse-fifo-lot-location-development-2026-11-08.md).

The new code **does not** mean warehouse FIFO integration is production-ready. Historic balances and lots without location evidence will require documented reconciliation; incomplete lot data deliberately prevents financial/production postings that could misstate FIFO costs.

## Still open in development

- Historical cost layers without position evidence and legacy physical stock that predates cost-layer tracking still need a reviewed migration. Newly developed FIFO transfers and issue controls deliberately refuse unsupported legacy attribution.
- Full warehouse-level lot quarantine, routing and transfer costing, stock recall and source-lot traceability throughout the manufacturing chain.
- Some supplier-return edge cases spanning multiple matched invoices or mixed invoiced/uninvoiced quantities require a reviewed multi-document credit workflow. Such cases are blocked by current single-document validation instead of silently crediting an unrelated payable.
- Finance posting of independently invoiced landed-cost providers, formal tax/discount policy and source-cost GL reconciliation remain outstanding.
- Migration of legacy source workbooks and explicit client acceptance of currency, inventory and supplier opening balances.

## Verification boundary

At the user's direction, automated tests, MySQL migrations, browser UAT, financial reconciliation and deployment were not executed during this batch. Commits confirm source changes, not runtime correctness. Keep `main` and production unchanged until separate validation is approved.
